# Репозитории (Repositories)

**Пространство имен:** `SchedulerDBManager.DataAccess.Repositories`

Этот модуль представляет собой слой доступа к данным (DAL) и реализует паттерн «Репозиторий». Он изолирует бизнес-логику от деталей выполнения SQL-запросов к СУБД MS Access.

---

## 1. Репозиторий пользователей

### Интерфейс: `IUserRepository`
* **Описание:** Описывает контракт управления учетными записями пользователей.

#### Методы:
* `IEnumerable<User> GetAll()`
    * **Описание:** Получает полный список всех зарегистрированных пользователей системы.
    * **Возвращает:** Коллекцию объектов [`User`](Models.md#4-user-пользователь-системы).

* `User GetByLogin(string login)`
    * **Описание:** Выполняет поиск пользователя по логину. Используется при авторизации и проверке логина на уникальность.
    * **Параметры:**
        * `login` — строка с логином пользователя.
    * **Возвращает:** Объект [`User`](Models.md#4-user-пользователь-системы), если пользователь найден. Иначе — `null`.

* `void Add(User user)`
    * **Описание:** Создает новую учетную запись в БД.
    * **Параметры:**
    * `user` — объект [`User`](Models.md#4-user-пользователь-системы) для добавления.

* `void Update(User user)`
    * **Описание:** Обновляет существующие данные пользователя (логин, пароль и роль).
    * **Параметры:**
        * `user` — объект [`User`](Models.md#4-user-пользователь-системы) с обновленными данными.

* `void Delete(int id)`
    * **Описание:** Удаляет пользователя из системы по его идентификатору.
    * **Параметры:**
        * `id` — уникальный идентификатор пользователя.

---

### Класс: `AccessUserRepository`
**Реализует:** [`IUserRepository`](#интерфейс-iuserrepository)

**Описание:** Реализация репозитория пользователей для СУБД MS Access. 

#### Конструкторы:
* `AccessUserRepository(IDatabase db)`
    * **Описание:** Инициализирует репозиторий и внедряет зависимость ядра базы данных.
    * **Параметры:**
        * `db` — объект, реализующий интерфейс [`IDatabase`](Database.md#интерфейс-idatabase).

---

## 2. Репозиторий подразделений

### Интерфейс: `IDepartmentRepository`
**Описание:** Описывает контракт управления подразделениями.

#### Методы:
* `IEnumerable<Department> GetAll()`
    * **Описание:** Возвращает список всех зарегистрированных подразделений.
    * **Возвращает:** Коллекцию объектов [`Department`](Models.md#1-department-подразделение).

* `IEnumerable<Department> SearchByName(string name)`
    * **Описание:** Выполняет поиск подразделений по частичному совпадению названия.
    * **Параметры:**
        * `name` — поисковый запрос (часть названия подразделения).
    * **Возвращает:** Коллекцию совпавших подразделений [`Department`](Models.md#1-department-подразделение).

* `void Add(Department department)`
    * **Описание:** Добавляет новое подразделение.
    * **Параметры:**
        * `department` — объект нового подразделения [`Department`](Models.md#1-department-подразделение).

* `void Update(Department department)`
    * **Описание:** Обновляет название и ФИО руководителя существующего подразделения.
    * **Параметры:**
        * `department` — объект подразделения [`Department`](Models.md#1-department-подразделение) с новыми данными.

* `void Delete(int id)`
    * **Описание:** Удаляет подразделение по его идентификатору.
    * **Параметры:**
        * `id` — уникальный идентификатор подразделения.

---

### Класс: `AccessDepartmentRepository`
**Реализует:** [`IDepartmentRepository`](#интерфейс-idepartmentrepository)

**Описание:** Реализация репозитория подразделений для MS Access. Поиск в методе `SearchByName` использует оператор `LIKE` с подстановочными знаками `%`.

#### Конструкторы:
* `AccessDepartmentRepository(IDatabase db)`
    * **Описание:** Инициализирует репозиторий и внедряет зависимость ядра базы данных.
    * **Параметры:**
        * `db` — объект, реализующий интерфейс [`IDatabase`](Database.md#интерфейс-idatabase).

---

## 3. Репозиторий производственных участков

### Интерфейс: `ISectionRepository`
**Описание:** Описывает контракт управления производственными участками.

#### Методы:
* `IEnumerable<Section> GetAll()`
    * **Описание:** Возвращает полный список участков.
    * **Возвращает:** Коллекцию объектов [`Section`](Models.md#2-section-участок).

* `IEnumerable<Section> SearchByAddress(string address)`
    * **Описание:** Выполняет поиск участков по частичному совпадению адреса.
    * **Параметры:**
        * `address` — поисковый запрос (часть адреса участка).
    * **Возвращает:** Коллекция совпавших участков [`Section`](Models.md#2-section-участок).

* `void Add(Section section)`
    * **Описание:** Добавляет новый производственный участок.
    * **Параметры:**
        * `section` — объект нового участка [`Section`](Models.md#2-section-участок).

* `void Update(Section section)`
    * **Описание:** Обновляет параметры участка (адрес, телефон, привязанное подразделение).
    * **Параметры:**
        * `section` — объект участка [`Section`](Models.md#2-section-участок) с обновленными данными.

* `void Delete(int id)`
    * **Описание:** Удаляет производственный участок по его идентификатору.
    * **Параметры:**
        * `id` — идентификатор участка.

---

### Класс: `AccessSectionRepository`
**Реализует:** [`ISectionRepository`](#интерфейс-isectionrepository)

**Описание:** Реализация репозитория участков для MS Access. 

*Особенность реализации:* Методы выборки данных (`GetAll`, `SearchByAddress`) используют `INNER JOIN` с таблицей `department` для автоматической подстановки текстового названия подразделения (`department_name`) в возвращаемые объекты `Section`.

#### Конструкторы:
* `AccessSectionRepository(IDatabase db)`
    * **Описание:** Инициализирует репозиторий и внедряет зависимость ядра базы данных.
    * **Параметры:**
        * `db` — объект, реализующий интерфейс `IDatabase`.

## 4. Репозиторий смен

### Интерфейс: [`IScheduleRepository`](#интерфейс-ischedulerepository)
**Описание:** Описывает контракт управления запланированными сменами.

#### Методы:
* `IEnumerable<Schedule> GetAll()`
    * **Описание:** Возвращает полный список запланированных рабочих смен.
    * **Возвращает:** Коллекцию объектов [`Schedule`](Models.md#3-schedule-смена).

* `IEnumerable<Schedule> SearchBySupervisor(string name)`
    * **Описание:** Ищет рабочие смены по ФИО начальника смены (по частичному совпадению).
    * **Параметры:**
        * `name` — часть ФИО начальника смены.
    * **Возвращает:** Коллекцию найденных смен [`Schedule`](Models.md#3-schedule-смена).

* `void Add(Schedule schedule)`
    * **Описание:** Создает новую запись о смене в базе данных.
    * **Параметры:**
        * `schedule` — объект создаваемой смены [`Schedule`](Models.md#3-schedule-смена).

* `void Update(Schedule schedule)`
    * **Описание:** Обновляет параметры существующей смены в базе данных.
    * **Параметры:**
        * `schedule` — объект смены [`Schedule`](Models.md#3-schedule-смена) с обновленными данными.

* `void Delete(int id)`
    * **Описание:** Удаляет смену из расписания по её идентификатору.
    * **Параметры:**
        * `id` — уникальный идентификатор смены.

---

### Класс: `AccessScheduleRepository`
**Реализует:** `IScheduleRepository`

**Описание:** Реализация репозитория смен для MS Access. 

*Особенность реализации:* Методы выборки данных используют `INNER JOIN` с таблицей `sections` для обогащения возвращаемого объекта `Schedule` физическим адресом участка (`address`)..

#### Конструкторы:
* `AccessScheduleRepository(IDatabase db)`
    * **Описание:** Инициализирует репозиторий и внедряет зависимость ядра базы данных.
    * **Параметры:**
        * `db` — объект, реализующий интерфейс [`IDatabase`](Database.md#интерфейс-idatabase).
