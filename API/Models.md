# Модели данных (Models)

**Пространство имен:** `SchedulerDBManager.DataAccess.Models`

Этот пакет содержит POCO-классы которые используются для передачи данных между всеми слоями приложения.

## 1. `Department` (Подразделение)
Описывает структуру подразделения внутри компании.
* `int DepartmentId` — Уникальный идентификатор (PK).
* `string DepartmentName` — Наименование подразделения.
* `string HeadFullName` — ФИО руководителя.

## 2. `Section` (Участок)
Описывает конкретный участок, привязанный к подразделению.
* `int SectionId` — Уникальный идентификатор (PK).
* `string Address` — Физический адрес.
* `int DepartmentId` — ID связанного подразделения (FK).
* `string DepartmentName` — Название подразделения *(Заполняется автоматически при загрузке из БД)*.
* `string Phone` — Контактный телефон участка.

## 3. `Schedule` (Смена)
Описывает запланированную смену на участке.
* `int ShiftId` — Уникальный идентификатор смены (PK).
* `DateTime StartTime` — Точные дата и время начала смены.
* `DateTime EndTime` — Точные дата и время окончания смены.
* `int Duration` — Длительность в часах *(Рассчитывается автоматически бизнес-логикой)*.
* `int WorkerCount` — Количество рабочих в смене.
* `string SupervisorFullname` — ФИО начальника смены.
* `int SectionId` — ID участка, где проходит смена (FK).
* `string SectionAddress` — Адрес участка *(Заполняется автоматически при загрузке из БД)*.
* `DateTime ShiftDate` — Дата смены без времени *(Рассчитывается автоматически бизнес-логикой)*.

## 4. `User` (Пользователь системы)
Модель учетной записи для авторизации и управления правами доступа.
* `int UserId` — Уникальный ID.
* `string Login` — Уникальный логин.
* `string Password` — Пароль пользователя.
* `int Role` — Уровень доступа *(1 - Читатель, 2 - Редактор, 3 - Администратор)*.
* `bool CanEditData` — Возвращает `true`, если `Role >= 2`.
* `bool IsAdmin` — Возвращает `true`, если `Role == 3`.
* `string RoleName` — Строковое представление роли ("Читатель", "Редактор", "Администратор").
