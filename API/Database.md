# База данных (Database)

**Пространство имен:** `SchedulerDBManager.DataAccess.Database`

Данный модуль отвечает за структуру БД и взаимодействие с файлом СУБД MS Access (`.accdb`) посредством библиотеки `OLE DB`.

---

## 1. Структура базы данных

БД состоит из 4 таблиц. Целостность данных обеспечивается с помощью каскадного удаления слоем сервисов (BusinessLogic).

### Таблица `users` (Пользователи)
Хранит учетные записи для авторизации в системе.
* `user_id` *(Счетчик, PK)* — Уникальный идентификатор.
* `login` *(Короткий текст)* — Уникальный логин пользователя.
* `password` *(Короткий текст)* — Пароль.
* `role` *(Числовой)* — Уровень привилегий (1 - Читатель, 2 - Редактор, 3 - Администратор).

### Таблица `department` (Подразделения)
Хранит информацию о подразделениях организации.
* `department_id` *(Счетчик, PK)* — Уникальный идентификатор.
* `department_name` *(Короткий текст)* — Название подразделения.
* `head_fullname` *(Короткий текст)* — ФИО руководителя.

### Таблица `sections` (Участки)
Хранит данные об участках, привязанных к подразделениям.
* `section_id` *(Счетчик, PK)* — Уникальный идентификатор.
* `address` *(Длинный текст)* — Физический адрес участка.
* `department_id` *(Числовой, FK)* — Внешний ключ, ссылка на `department.department_id`.
* `phone` *(Короткий текст)* — Контактный телефон участка.

### Таблица `schedule` (Смены)
Журнал запланированных рабочих смен.
* `shift_id` *(Счетчик, PK)* — Уникальный идентификатор.
* `start_time` *(Дата/время)* — Точные дата и время начала смены.
* `end_time` *(Дата/время)* — Точные дата и время окончания смены.
* `duration` *(Числовой)* — Длительность смены в часах.
* `worker_count` *(Числовой)* — Количество рабочих на смене.
* `supervisor_fullname` *(Короткий текст)* — ФИО ответственного начальника.
* `section_id` *(Числовой, FK)* — Внешний ключ, ссылка на `sections.section_id`.
* `shift_date` *(Дата/время)* — Дата смены.

## 2. Программный интерфейс доступа к данным

### Интерфейс: `IDatabase`
**Описание:** Абстракция для выполнения запросов к реляционной БД.

#### Методы:

`DataTable ExecuteSelect(string query, params OleDbParameter[] parameters)`

**Описание:** Выполняет параметризованный SQL-запрос на чтение данных.

**Аргументы:**
* `query` — строка SQL-запроса (`SELECT`).
* `parameters` — массив параметров OLE DB для подстановки в запрос.

**Возвращает:** Объект `DataTable` с результатами выборки.
  
`void ExecuteNonQuery(string query, params OleDbParameter[] parameters)`

**Описание:** Выполняет параметризованный SQL-запрос на модификацию данных.

**Параметры:**
* `query` — строка SQL-запроса (`INSERT`, `UPDATE`, `DELETE`).
* `parameters` — массив параметров.

---

### Класс: `AccessDatabase`
**Реализует:** [`IDatabase`](#интерфейс-idatabase)

**Описание:** Реализация ядра БД для Microsoft Access с использованием драйвера `Microsoft.ACE.OLEDB.12.0`. Обеспечивает безопасное выполнение запросов (защита от SQL-инъекций через параметризацию).

#### Конструкторы:
`AccessDatabase(string databasePath = "ShiftSchedule.accdb")`

**Описание:** Инициализирует объект базы данных и формирует строку подключения.

**Параметры:**
* `databasePath` — путь к файлу базы данных.

**Исключения:**
* `ArgumentException` — выбрасывается, если переданный путь пуст или состоит из пробелов.

#### Методы:
`void CheckConnection()`

**Описание:** Выполняет тестовое открытие и закрытие соединения. Служит для проверки соединения с БД.

**Исключения:**
* `Exception` — генерируется с user-friendly текстом поверх оригинальных системных исключений:
    * При `OleDbException`: "Ошибка: Драйвер Microsoft.ACE.OLEDB.12.0 НЕ установлен в системе.".
    * При `InvalidOperationException`: "Ошибка: Провайдер данных ACE.OLEDB.12.0 не зарегистрирован на этом компьютере.".
    * При `BadImageFormatException` -> "Ошибка: Конфликт разрядности! Приложение пытается загрузить драйвер не той архитектуры.".
    * При `COMException`: Сообщение с кодом системной ошибки.
